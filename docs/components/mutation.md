# Mutation

`GA` (`saealib.GA`) delegates adding perturbation to the offspring generated by crossover to `Mutation`, a swappable operator.
To change the mutation scheme, you only need to swap out this `Mutation`, not `GA` itself.

## Mutation's role

`Mutation` requires only one method, `mutate(p, mutate_range, rng=...)`, to be implemented.
`p` receives the individual to be mutated with shape `(dim,)`, and returns the mutated individual with the same shape `(dim,)`.
`mutate_range` receives the design variables' lower and upper bounds as a `(lb, ub)` tuple.

The individual-level mutation probability is held by the class attribute `prob`.
Whereas for `Crossover` the decision of whether to perform crossover was `GA`'s responsibility, for `Mutation` this decision is made by `mutate()`'s implementation itself.
Every built-in class checks `rng.random() >= self.prob` at the top of `mutate()`, and if not satisfied, simply duplicates and returns the individual as-is.
This means `GA` doesn't need to be aware of the individual-level probability at all — it just calls `mutate()` unconditionally on every selected individual.
Note that when implementing a custom `Mutation`, you need to write this `prob` check yourself.

The other class attribute, `prob_var`, is the per-variable mutation probability.
When `None`, it resolves to `min(0.5, 1/dim)` when `mutate()` is called.

## Built-in Mutations

| Class | Parameters | Characteristics |
|---|---|---|
| `MutationUniform` | `prob, *, prob_var=None` | Replaces a chosen dimension with a uniform random value from `[lb, ub]` |
| `MutationGaussian` | `prob, *, sigma, prob_var=None` | Adds `N(0, sigma)` Gaussian perturbation to a chosen dimension {cite}`rechenberg1973es` |
| `MutationPolynomial` | `prob, *, eta, prob_var=None` | Polynomial mutation {cite}`deb2001mooea`. Larger `eta` gives a smaller perturbation |
| `MutationIntegerUniform` | `prob, *, prob_var=None` | Replaces with a uniform random integer in `[lb[i], ub[i]]` (inclusive). For integer variables |
| `MutationCategorical` | `prob, *, prob_var=None` | Replaces the category index with a uniform random integer from `{0, ..., n_categories-1}`. For categorical variables |

For problems with only continuous variables, pick one of these and pass it to `GA(mutation=..., ...)`.
The basic decision is: choose `MutationUniform` if you want the search's coarseness matched to the variable's own value range, or `MutationGaussian` or `MutationPolynomial` if you want to perturb only the neighborhood of the existing value.
`MutationGaussian` specifies the perturbation magnitude directly via `sigma`, whereas `MutationPolynomial` specifies the concentration of the perturbation via `eta` (the distribution index), with the perturbation width relative to the value range determined automatically.
`MutationIntegerUniform` and `MutationCategorical` merely share a common private implementation for how the random number is generated (replacement with a uniform random integer within the value range), but are treated as separate classes in the public API.

For problems where design variables mix integer and categorical variables, `GA` uses a different `Mutation` instance per variable type.
If the `GA` constructor's `integer_mutation`/`categorical_mutation` arguments are omitted, `MutationIntegerUniform`/`MutationCategorical` are supplied automatically (with `prob_var` inherited from the continuous-variable `mutation`).
`GA.ask()` splits individuals into columns by variable type, applies each `Mutation` only to its corresponding columns, and then reassembles the results.
The correspondence between variable types and `Mutation` is determined by [Problem](problem.md)'s `variables` argument.

```{note}
Only `MutationUniform` is currently `@register()`ed; the other 4 classes are not yet registered with the Registry.
Keep this difference in mind if you resolve classes from strings via the Registry.
```

## Extension hooks

If you just want to add post-processing, such as rounding values that fall outside the bounds, you can add it to an existing `Mutation` instance with `with_post(fn)` instead of creating a new subclass.
`with_post` doesn't modify the original instance — it returns a copy with `fn` added.

```python
import numpy as np
from saealib import MutationUniform


def clip_offspring(offspring, mutate_range, rng, ctx=None):
    lb, ub = mutate_range
    return np.clip(offspring, lb, ub)


base = MutationUniform(prob=1.0)
clipped = base.with_post(clip_offspring)
```

`fn`'s signature is `fn(offspring, mutate_range, rng, ctx) -> np.ndarray`, receiving the result of the existing hook (by default an identity function that does nothing) and returning an additional transformation.
Calling `with_post` multiple times chains the hooks in the order called.

## Implementing a custom Mutation

If you need a custom mutation scheme, subclass `Mutation` and implement only `mutate()`.
The following example is a simple mutation that replaces a chosen dimension with the midpoint of its value range.

```python
import numpy as np
from saealib import Mutation


class MidpointMutation(Mutation):
    def __init__(self, prob: float = 1.0, *, prob_var: float | None = None):
        super().__init__()
        self.prob = prob
        self.prob_var = prob_var

    def mutate(self, p, mutate_range, rng=np.random.default_rng()):
        if rng.random() >= self.prob:
            return p.copy()
        dim = len(p)
        p_var = self.prob_var if self.prob_var is not None else min(0.5, 1.0 / dim)
        c = p.copy()
        lb, ub = mutate_range
        for i in range(dim):
            if rng.random() < p_var:
                c[i] = (lb[i] + ub[i]) / 2.0
        return c
```

Both the individual-level check via `prob` and the variable-level check via `prob_var` need to be written yourself, following the same convention as the built-in classes.
Omitting these checks results in an implementation where every dimension always mutates.
